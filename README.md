## Документация
Описание методов доступно по ссылке [http://localhost:5091/swagger](http://localhost:5091/swagger) после запуска приложения.

В сервисе используется доменная модель мероприятий (**Event**), обладающая следующими полями:

|Наименование  |Описание                     |Тип (**C#**) |Обязательное поле
|:------------ |:--------                    |:--------    |:--------:
|Id            |Идентификатор                |Guid         | +          
|Title         |Наименование                 |string       | +          
|Description   |Описание                     |string?      | -          
|TotalSeats    |Всего мест на событии        |int          | +        
|AvailableSeats|Количество свободных мест    |int          | +        
|StartAt       |Дата начала мероприятия      |DateTime     | +         
|EndAt         |Дата окончания мероприятия   |DateTime     | +         

<br>Для управления мероприятиями в сервисе используются следующие запросы API:

Запрос **GET/Events** позволяет получить созданные в сервисе мероприятия. Включает следующие параметры для фильтрации:

|Наименование  |Описание                     |Тип               |Опциональный|Значение по умолчанию
|:------------ |:--------                    |:--------         |:--------:  |:--------:
|title         |Фильтр по наименованию       |string            | +          | -
|from          |Фильтрация по дате начала    |string($date-time)| +          | -
|to            |Фильтрация по дате окончания |string($date-time)| +          | -
|page          |Номер страницы               |integer           | +          | 1
|pageSize      |Число элементов на странице  |integer           | +          | 10

Фильтр применяется только если параметры переданы; все фильтры работают одновременно (Логическое И).

**Пример запроса:** [http://localhost:5091/Events?from=2026-09-01&to=2026-09-16&page=1&pageSize=10](http://localhost:5091/Events?from=2026-09-01&to=2026-09-16&page=1&pageSize=10)

**Пример ответа:**
```
{

      "endAt": "2026-09-02T12:25:22.6109258+03:00",

Iure nisi assumenda accusantium voluptatum aliquam expedita iusto ipsam."
    }
  ],
  "total": 1,
  "page": 1,
  "count": 1,
  "totalPages": 1,
  "hasNext": false,
  "hasPrevious": false,

```
* items - массив элементов на странице
* total - всего элементов по фильтрации
* page -  номер страницы
* count - число элементов на странице
* totalPages - всего страниц
* hasNext - есть ли следующая страница
* hasPrevious - есть ли предыдущая страница
* pageSize - максимальнов возможное число элементов на странице

Запрос **GET /Events/{id}** позволяет получить конкретное мероприятие по его идентификатору. Если мероприятие не найдено, возвращает статус 404.\
Запрос **POST /Events** позволяет создать новое мероприятие в сервисе. При создании указывается общее количество мест на мероприятии, доступных для бронирования. При  этом количество доступных мест при создании равно общему количеству мест. Возвращает статус 201 и ссылку на адрес API для отображения мероприятия.\
Запрос **PUT /Events** позволяет обновить существующее мероприятие в сервисе. Возвращает статус 204, если мероприятие обновлено. 404, если мероприятие не найдено.\
Запрос **DELETE /Events** позволяет удалить мероприятие. Возвращает статус 204, если мероприятие удалено. 404, если мероприятие не найдено.

**Внимание!** При создании/изменении мероприятий используются DTO-модели, подробно описанные в [Swagger'е](http://localhost:5091/swagger).

Для управление бронированием мероприятий в сервисе используется доменная модель (**Booking**), обладающая следующими полями:

|Наименование  |Описание                     |Тип (**C#**)      |Обязательное поле
|:------------ |:--------                    |:--------         |:--------:
|Id            |Идентификатор брони          |Guid              | +          
|EventId       |Идентификатор мероприятия    |Guid              | +          
|Status        |Статус брони                 |enum BookingStatus| +        
|CreatedAt     |Дата создания                |DateTime          | +         
|ProcessedAt   |Дата обработки брони         |DateTime?         | -         

где BookingStatus может принимать следующие значения: 
* 0 - интерпретируется как **Pending** (Бронь создана, ожидает обработки);
* 1 - интерпретируется как **Confirmed** (Бронь подтверждена);
* 2 - интерпретируется как **Rejected** (Бронь отклонена).

Запрос **POST /Events/{id}/book** позволяет создать бронь на мероприятие. Бронь создаётся в статусе 0, пользователю возвращается информация о созданной брони. Метод возвращает статус 202 (если бронь удачно создана). Если свободных мест на событии не осталось, метод возвращает статус 409. Если пытаются создать бронь на событие, которое уже началось, метод вернёт статус 400. Если попытаются создать бронь для несуществующего события, то метод вернёт статус 404.\
Запрос **GET /Bookings/{id}** позволяет узнать статус созданной брони. Если бронь не найдена, возвращает статус 404.

**Механизм работы с бронированием:**  Созданная бронь со статусом **0** обрабабатывается сервисом в фоновом режиме, в итоге получает свой окончательный статус: **1 (Подтверждена)** или **2 (Отклонена)** (Бронь может быть отклонена, если мероприятие уже началось, мероприятие не найдено). Для обработанной брони выставляется дата/время в **ProcessedAt**. Узнать статус бронирования можно, периодически запрашивая информацию о нём, с помощью метода **GET/Bookings/{id}**.

**Сценарий с овербукингом:** Необходимо создать событие с количеством мест > 0 (например, 3). Три запроса на создание брони на мероприятие должны выполниться успешно (статус 202) Четвёртый должен завершиться ошибочно (код завершеня метода - 409).

Для защиты **кртитических секций** в сервисе бронирования (BookingService) используются примитивы синхронизации: **lock-object** и **SemaphoreSlim**. **lock** позволяет только одной задаче/потоку находиться в критической секции в определённый момент времени (блокирующий доступ, не работает с асинхронным кодом).**SemaphoreSlim** позволяет ограничить количество потоков, которые одновременно могут работать в критической секции (имеет возможность неблокирующего ожидания благодаря **WaitAsync**). При SemaphoreSlim(1, 1) ведёт себя аналогично lock с **async-поддержкой**.


**Внимание! Для ислючительных ситуаций, которые могут возникнуть при выполнении запросов API, используется формат Problem Details (RFC 7807):** [Ссылка на документ](https://datatracker.ietf.org/doc/html/rfc7807)
